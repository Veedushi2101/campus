# Security Architecture

- **Authoritative Express API Boundary**: React never queries PostgreSQL tables directly via Supabase Data API (`supabase.from(...)`). `@supabase/supabase-js` is used strictly for Authentication; all business reads and writes flow through Express (`/api/v1/*`) with `Authorization: Bearer <access_token>`.
- **Cryptographic JWT Verification**: `server/shared/auth/supabaseAuth.ts` verifies asymmetric Supabase `ES256`/`RS256` JWTs against cached JWKS (`/auth/v1/.well-known/jwks.json` with automatic key-rotation refresh), supports `HS256` fallback when `SUPABASE_JWT_SECRET` is configured, validates token expiration and issuer, and enforces `emailVerified === true` and `INSTITUTIONAL_EMAIL_DOMAINS`.
- **Bootstrap Super Admin Control**: `SUPER_ADMIN_BOOTSTRAP_EMAILS` grants initial `super_admin` privileges only on authenticated verification of matching emails. Database triggers (`prevent_user_privilege_escalation`, `prevent_club_privilege_escalation`, and `prevent_club_admin_membership_escalation`) block non-admin modifications to `users.global_role`, `users.account_status`, `clubs.status`, `clubs.follower_count`, and `club_admin` memberships.
- **Database Privilege Separation & RLS**: `campusverse_app` (`NOSUPERUSER`, `NOBYPASSRLS`) enforces Row-Level Security across all 17 tables using transaction-local `set_config(..., ..., true)`, blocks unauthenticated (`public`) reads on `users`, isolates private student `registrations`, `notifications`, `finance_reports`, and restricts `audit_logs` to append-only (`SELECT, INSERT`).
- **PII & Profile Mass-Assignment Protection**: `PATCH /api/v1/users/me` uses `.strict()` Zod validation rejecting `globalRole`, `accountStatus`, `email`, or `studentId`, and public `GET /api/v1/clubs/:clubId` redacts team `userEmail` fields unless the caller is Super Admin or Club Admin for that club.
- **QR Privacy**: QR codes contain opaque random tokens (`CV-QR-...`) matched server-side via SHA-256 `qr_token_hash`, with zero embedded PII and never logged in `audit_logs`.
- **Strict Demo Isolation**: `DemoDataAdapter` and `/api/v1/auth/demo-*` are permanently disabled when PostgreSQL is configured or `NODE_ENV === 'production'`.
